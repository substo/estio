# Studio voices, provider keys and local models (design, 2026-11-23)

Owner decisions: nothing provider- or voice-specific lives in `.env`; our own Location uses the product exactly as a customer would; voices are created and chosen in the product; local models are installed from a catalog like Ollama, per task, with detection.

## Decisions

1. **Keys are per Location, in the product.** Fish Audio and ElevenLabs keys are encrypted Location secrets (`settingsService`, `LOCATION_AI` domain, new `FISH_API_KEY` / `ELEVENLABS_API_KEY` secret keys) entered in Settings -> AI beside the OpenAI/Google keys, with the same connection-status and usage rules. No `.env` key, voice id or provider selector is read by any app or companion code. The temporary `.env` block and `lib/studio/video-assembly/tts.ts` env/file reading are removed.
2. **Secrets stay on the server.** Hosted voice generation (Fish, ElevenLabs) runs server-side with the Location's key, never on the Mac and never in a job payload. The Make-video flow first renders the narration beats on the server, stores them as private Studio media, and the Mac job receives download links for `voice-NN.mp3` like footage. On-device voice is the other path: the job carries `{engine:"local", model, voice}` and the Mac generates.
3. **Voice library.** `studio.studio_voices` per Location: provider (`fish`|`elevenlabs`|`local`), provider voice id, display name, kind (`preset`|`clone`), language, optional persona/owner label, default flag, consent record for clones (who, when, statement; sample upload id), created_by. Presets are synced from the provider (Fish `GET /model`, ElevenLabs `GET /v1/voices`); clones are created from an uploaded sample through the provider's clone API (Fish `POST /model`, ElevenLabs `POST /v1/voices/add`) only after an explicit "this is my voice or I have the speaker's permission" attestation, audited. Voices are chosen per piece in Make video, with a Location default; personas/users pick from the same library.
4. **Local models are a catalog, not code.** A reviewed catalog (task, model, repo/revision, size, RAM floor, languages, licence) drives Settings -> Connected computer -> Local models: detected (already on disk), install, remove, status. The Mac companion reports installed models in its heartbeat; install/remove arrive as device commands (same channel as provider login), download with progress, verify, then mark ready. First pairing asks which tasks to run locally and recommends models that fit the reported RAM/disk (8 GB Mac: Qwen3-TTS 0.6B 4-bit, Parakeet). Local use never silently becomes paid use and paid never silently becomes local.
5. **Routing.** Per task (voice, transcription, text) an ordered choice: local model installed on a paired Mac, own Location key, then nothing (no hidden platform key). Shown in the same settings page as the existing AI route.

## Slices

- **Voices (A+B+C):** keys in Settings -> AI, voice library + clone flow, server-side narration, Make-video voice picker, remove env reading.
- **Local models (D+E):** catalog, detection, install/remove commands, Settings UI, first-run prompt.

## Local models: as built (feature/studio-local-models)

- **Catalog:** `lib/studio/local-models.ts` (version 1): Qwen3-TTS 0.6B 4-bit (voice, speakers serena/vivian/uncle_fu/ryan/aiden/ono_anna/sohee/eric/dylan) and Parakeet TDT 0.6B v3 (transcription weights), each with a pinned Hugging Face revision, size, RAM/disk floors, licence and the weight files that must exist. Licence/language fields are from the model cards as understood at the time and still need a human review.
- **Channel:** no SQL. The desired list is `models` in the existing versioned device config (`save_config`, acknowledged by the Mac), validated against catalog ids by `readDeviceConfig`. Removing an id from the list cancels an install or removes a model this app installed. Older saved configs have no `models` key and stay valid.
- **Mac:** `lib/studio/companion/model-manager.ts`. Detection checks that weight files resolve and are large enough (a folder or partial download is not "installed"). Install = create the isolated venv, pip install the runtime package, `snapshot_download(repo, revision)` with fixed argv, verify, record in `models.json`. Models already on the Mac are reported as "found" and are never deleted by this app. One download at a time; refused when memory/disk cannot hold the model; waits for AC power unless Setup allows battery. Progress is a heartbeat per 10%.
- **Report:** `modelStates` in the heartbeat capabilities, whitelisted by `safeDeviceCapabilities`.
- **UI:** Settings -> Connected computer -> Local models (list, fit warnings, install/cancel/remove) and a first-run prompt (which tasks should this Mac run itself, install recommended / not now) shown once the Mac has reported and no choice has been saved. The pairing approval text points to it; the Mac cannot report hardware until after approval, so recommendations are made right after pairing.
- **Voice path:** `synthesizeLocal`/`localTtsReady` in `lib/studio/video-assembly/tts.ts` now read the model, speaker and installed-check from the catalog.
- **Not here:** parakeet-mlx runtime install (the transcription installer owns it; the catalog entry fetches weights only), text models via Ollama/LM Studio (detection exists, no install), provider keys and the voices table (voices fork).

## As built: voices studio (2026-11-23, local candidate, not deployed)

- **Where.** Voices lives under Settings -> Voices (`/settings/voices`), not in the Studio sidebar; the voice picker stays inline in Make video with a "Manage voices" link, and lists only voices that can run now. The old `/studio/voices` route is gone (no redirect).
- **Library.** Search, quick filters (Available, On this Mac, Hosted, Cloned, Needs a key) and trait chips (gender, age, tone, use, accent) filter client-side. Voices that cannot run yet (no key, model not installed, Mac offline) sit in a collapsed "Not connected" group with a link to Settings -> AI or Devices. Descriptions and tags come from ElevenLabs `labels`/`description`; Fish `tags`/`description` are read defensively (field names not confirmed against Fish's OpenAPI); built-in speakers have hand-written descriptors (`LOCAL_SPEAKER_CATALOG`, from the Qwen3-TTS model card, not machine-verified). Migration `20261130100000_studio_voices_studio` adds `description`, `tags` and the `designed` kind.
- **Create a voice.** Record (MediaRecorder with level meter; spoken consent sentence bound to the voice name, then three passages; minimum 30 s; one take), Upload, or Design from a description (ElevenLabs `POST /v1/text-to-voice/design` then `POST /v1/text-to-voice`; up to three candidates, nothing saved until one is chosen). The typed consent attestation and audit stay. The spoken consent is stored as text; Studio does not verify the recording's words. Fish has no design endpoint, so Design needs ElevenLabs.
- **Local preview.** `studio.voice_preview` job: the Mac generates a ~4 s mono sample with the installed on-device model and returns it inside the job result (<= 24,000 base64 characters, under the 32 KiB device body bound); the page polls and plays it. The device kind must be granted in `allowed_kinds` by the edit-loop migration; this migration only adds the enqueue function, release trigger and the device wrapper `studio_voice_preview_device_command`, which sits in front of `studio_video_assembly_device_command` (merge note: whichever branch lands second must chain its wrapper in front of the other).
- **Assistant.** "Ask about voices" is a browser-side, LLM-free helper over the same tools (find, compare, preview, set default, prefill the Design form). It is not a model-backed chat: the Studio agent is record-bound with its own conversation tables, typed steps and consent flow. A model-backed voices chat needs a record-less conversation scope and a new tool allowlist; that is a separate task.

## Voice cloning and design: findings (2026-11-24)

Checked against the providers' own documentation through search results; I did not call any paid API, so request shapes below are verified against docs, not against a live response.

**ElevenLabs instant clone** (`POST /v1/voices/add`, multipart). `name` and `files` are required; `description`, `labels` (JSON string) and `remove_background_noise` (boolean, default off) are optional. Docs recommend 1 to 2 minutes of clean single-speaker audio; the minimum is about 10 s in total and 5 s per file; clarity beats length. They recommend MP3 at 192 kbps or more and warn uncompressed formats do not improve quality and can cause upload problems. Not verified: a maximum file size.
Sources: elevenlabs.io/docs/api-reference/voices/ivc/create, elevenlabs.io/docs/creative-platform/voices/voice-cloning/instant-voice-cloning.

**ElevenLabs Voice Design.** `POST /v1/text-to-voice/design` takes `voice_description` (20 to 1,000 characters) and returns previews with `generated_voice_id` and base64 MP3. We send `auto_generate_text: true`, or `text` (100 to 1,000 characters) when the owner supplies a preview line. `POST /v1/text-to-voice` saves one with `voice_name`, `voice_description`, `generated_voice_id`. Not verified: the exact English name of the flag that returns only ids, and `auto_generate_text` (the search result did not show it; the existing code already used it).
Sources: elevenlabs.io/docs/api-reference/text-to-voice/design, .../text-to-voice/create.

**Fish Audio** (`POST /model`, multipart). `type=tts`, `title`, `train_mode` (`fast` is the default and is usable immediately) and `voices` (repeated file field) are required. `texts` (one transcript per sample) improves quality; `visibility`, `description`, `enhance_audio_quality` and `cover_image` are optional. At least 10 s per sample; 30 to 60 clean seconds is the practical target. Not verified: a documented maximum length or the full `visibility` value list; a third party says `cover_image` is needed for public models (we create private ones).
Sources: docs.fish.audio/api-reference/endpoint/model/create-model, docs.fish.audio/developer-guide/core-features/creating-models.

**Why the owner saw "declined (400)".** The browser sent MediaRecorder WebM/Opus. The docs favour MP3/WAV, and nothing in them promises WebM. The provider's reason is now shown (bb6ed951). The recorder now produces 24 kHz mono 16-bit PCM WAV, and the sample length is checked per provider before any paid call. I could not reproduce the 400 against the real provider without a key, so "WebM was the cause" is the most likely explanation, not a confirmed one.

**Local cloning** (mlx-audio 0.6.7, Qwen3-TTS 12Hz 0.6B Base 4-bit, Apache-2.0). `--ref_audio` plus `--ref_text` give zero-shot cloning; the transcript should match the clip. Verified on this Mac: a 5.1 s clone of a new sentence was generated, and offline Parakeet transcribed it back exactly. Base is a separate install (1.7 GB) from CustomVoice; the catalog pins revision `0d6bb6fe`. Whether it resembles the reference voice was not judged by ear here.

**Not researched in depth:** Descript, Resemble and Cartesia flows (not compared; time went to the two providers we integrate).

### What the app does now
- Recording is WAV with a live length meter (minimum, good, maximum per target: ElevenLabs 20/60/180 s, Fish 15/30/90 s, this Mac 8/15/30 s). These thresholds are our own conservative choices above the documented minimums.
- "On this Mac" clones keep the reference WAV and transcript in private storage (`<location>/voice-refs/<voice id>.*`) only so the owner's Mac can fetch them at claim time; they are cached under `~/Library/Application Support/Estio/StudioCompanion/voices/<voice id>/`. Deleting the voice removes the stored copy; the Mac cache is kept until that folder is deleted. Nothing goes to a voice provider.
- Consent is recorded exactly like a hosted clone (`consent.where = on-device`).
