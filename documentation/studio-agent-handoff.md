## Original approved product brief

Build one hosted Next.js/TypeScript application and deployment based on Estio, with two host-based branded experiences and one shared Studio implementation. The Estio domain keeps its location selector and Business area (contacts, companies, conversations, websites, properties) and adds a Studio switch. The Substo domain shows its own login and workspace selector and Studio only. Estio and Substo use separate Clerk applications; equal email addresses do not merge identities or content. Resolve an exact allowlisted host/brand before Estio's public customer-website routing. Retain public tenant websites.

Keep Estio Business in its current Prisma database. Put all Studio workspaces and content for both brands in the dedicated Substo Supabase Postgres project, with media bytes in a private Cloudflare R2 bucket (decided 2026-10-23; the original brief said Supabase Storage, but Estio uses Cloudflare R2/Images, so Supabase holds Studio metadata only). Map one Studio workspace to each Estio location idempotently; Estio Studio access inherits the audited Estio location/team roles. Standalone Substo uses workspace memberships and invitations. Every Studio row/job is workspace scoped, and the server authorizes each request. Never infer access from email or trust a client-supplied workspace ID. Do not mutate the existing personal `owner_id` schema to simulate Clerk workspaces.

The first hosted release ports Substo's working research library, knowledge, ideas, scripts, content pipeline, media, and schedules. Import existing local `store.json`, SQLite knowledge, sidecars, and eventually media with counts, links, citations, review history, exact transcript/script text, and provenance intact. Treat imported legacy data as private. The first library and knowledge import paths implemented so far handle metadata, not a full cutover. Recording, native editor/companion sync, local model processing, covers, publishing, and generalized Business features come later. Keep the existing Swift `.substo` video editor; it need not be rewritten.

Hosted Studio and its durable jobs must function when the owner's Mac is off. Launch AI processing with a customer-supplied OpenAI API key per workspace for text and authorized upload transcription. Encrypt keys, meter and cap usage per workspace, and show retries and failures. Use provider adapters for later Claude/local models. Never use the operator's Codex or Claude subscription as the hosted customer runtime. The local Substo Codex integration is a reference, not a production dependency. Google OAuth scopes and refreshed tokens belong to each app user profile, keyed by app realm and Clerk user ID, never to a Studio workspace (user clarification 2026-10-24). Studio separately checks workspace access; subscriptions remain private to the connected user, and saving a public research link explicitly shares it. Hosted YouTube discovery should use Google OAuth for authorized subscriptions plus approved public channels, search, and saved URLs with honest provenance. The official API does not provide a personalized YouTube home feed; do not host signed-in browser scraping or label public search as personal recommendations. Third-party videos stay research links unless use of transcript/media is authorized. Automatically transcribe the customer's own uploads. Add a durable workspace-scoped worker alongside Next.js. Later the optional Mac companion may sync projects/media/edit status and accept scoped local-model work while online; hosted processing remains dependable.

For example `npx tsx --test lib/studio/knowledge-policy.test.ts` for a review policy edit, or the matching importer test for parser work. Use synthetic fixtures.
